KEY DECISIONS / THINGS OTHER MODULES MUST KNOW:
1. Opacity modifiers: spec palette colors are `var(--x)` so `bg-accent/10`, `text-danger/80`, `border-line/50` DO NOT generate CSS in Tailwind 3. Use the HSL shadcn twins instead: `bg-primary/10` (=accent), `text-destructive/80` (=danger), `border-border/50`, `bg-card/60` (=surface), `bg-popover/60` (=bg-elevated), `text-muted-foreground/70` (=text-muted), `ring-ring/25`. For violet/mint tints use arbitrary hex: `bg-[#7C5CFF]/15`, `text-[#00FFB2]`. `warning` is hex so `bg-warning/10` works.
2. --destructive-foreground is the dark base (#060810) because white on #FF4D6D is only 3.2:1 (fails AA); dark text gives 6.2:1. Destructive/default/gradient buttons therefore use `text-bg-base`. Violet #7C5CFF as small text on surface is 3.99:1 — use it for backgrounds/gradients only.
3. Components with user-facing text (DialogContent/SheetContent close button, CommandDialog/CommandEmpty, Calendar, NumberStepper) call `useLocale()/useT()` from '@/i18n/client' and therefore need LocaleProvider (always present under the root layout; global-error.tsx is outside and uses no primitives). In vitest, mock '@/i18n/client' (see tests/design-system.test.tsx for a ready pattern) — LocaleProvider depends on next/navigation and vitest's esbuild uses classic JSX so src/i18n/client.tsx cannot render in tests as-is. Also vitest jsdom does not expose window.localStorage (the test file has a stub); useLocalStorage degrades to in-memory when storage throws.
4. Calendar takes `locale` prop override; defaults to context locale. Weekday headers are 2-letter (Du…Ya / Пн…Вс), month title capitalized ("Sentabr 2026"/"Сентябрь 2026"). Roving tabindex + full keyboard nav (arrows, Home/End, PageUp/Down, Shift+PageUp/Down = year).
5. NumberStepper: `allowHalf=false` forces step to whole numbers (0.5 → 1) and snaps typed values; clamps to [min ?? step, max ?? 99] using snapQuantity/formatQuantity from '@/lib/calc' for 0.5/1 steps. Input has role=spinbutton (ArrowUp/Down, Enter commits, Escape reverts); the pure `normalizeStepperValue` is exported for tests/forms.
6. Segmented uses framer-motion layoutId (LayoutGroup scoped by useId, so multiple instances don't cross-animate); `variant='accent'` gives the gradient pill (nice for Adult/Child, with/without medicine toggles). Respects reduced motion.
7. Skeleton uses the `.shimmer` class with self-contained `@keyframes ds-shimmer` (Tailwind's `animate-shimmer` keyframes are only emitted when that utility is used somewhere).
8. Sonner is themed to the palette via `--normal-bg/--normal-border/--normal-text` overrides in globals.css; `.no-print` also hides the toaster when printing; `@page { margin: 8mm }`.
9. Spinner is provider-free: pass `label` for role=status, otherwise it is aria-hidden (decorative). Progress is hand-rolled (no @radix-ui/react-progress installed).
10. Tooltip.tsx was left untouched. public/robots.txt sitemap points to https://lor.uz/sitemap.xml (also disallows /print). manifest start_url=/dashboard with Navbat/Bemorlar/Kassa shortcuts.

KEY DECISIONS other modules should know:
1. Zod error messages in src/lib/auth/schemas.ts are i18n KEYS (e.g. 'common.validation.required', 'auth.validation.passwordWeak'); forms render `t(errors.x.message)`. Server validation `details` therefore contain keys too.
2. LoginSchema lowercases+trims login (matches authorize()); password is NOT trimmed. ResetSchema token is lenient (16–256 chars) — validity is decided by the DB lookup, so a bad token yields 404 NOT_FOUND (client maps NOT_FOUND → invalid-link state), never a 400.
3. Reset flow is DoS-aware: `findValidResetToken` (cheap read) runs BEFORE bcrypt hashing; then one transaction consumes the token (updateMany count guard against double-use races), updates password, bumps sessionVersion (invalidates all JWT sessions on next DB recheck), revokes remaining tokens and audits. LoginAttempt rows for that login are deleted afterwards so a locked-out user can sign in immediately.
4. Forgot endpoint rate-limits per IP with key `rateLimitKey('forgot', ip)` = 'forgot|<ip>' by recording every request as a failed LoginAttempt (5/15 min), and ALWAYS returns {sent:true}. Only active users in active clinics with an email get a token. Email locale comes from getLocale() (NEXT_LOCALE cookie / Accept-Language). Reset URL = (APP_URL || NEXTAUTH_URL || http://localhost:3000) + '/reset-password?token=…'.
5. email.ts: nodemailer is loaded via dynamic import only when SMTP_HOST is non-empty; otherwise the mail (To/Subject/text body incl. the reset link) is printed with console.info in a boxed 'LOR CRM · DEV MAIL' banner — the documented dev fallback. No 'server-only' import so the template is unit-testable. resetEmailTemplate is bilingual: primary locale card + short secondary-language block below.
6. "Remember" checkbox on login is an honest feature: it remembers the LOGIN NAME in localStorage ('lor:remember-login') and prefills it — NextAuth cookie lifetime (30 d) is fixed in options.ts and cannot be changed per request.
7. Login success does router.push(callbackUrl) + router.refresh(); callbackUrl is sanitized server-side (must start with '/', not '//' or '/\\', no CR/LF, not /login) — searchParams are read in the page (not useSearchParams), so no Suspense boundary is needed. Pages are force-dynamic with generateMetadata via getT() (localized <title>, noindex).
8. Demo credentials block renders only when the page passes showDemo (NEXT_PUBLIC_SHOW_DEMO_CREDS === '1'); clicking an account fills login+password and focuses the password field. Credentials match prisma/seed-data/users.ts.
9. AuthVisual is decorative: the <aside> is aria-hidden; ticker slows to 8 s and uses opacity-only transitions under prefers-reduced-motion, float/aurora/pulse classes are dropped. Uses opacity-safe token twins per design-system notes (bg-primary/10, border-border/70, hex for mint/violet).
10. Audit action 'PASSWORD_RESET' is written twice per flow: {step:'requested', delivered, expiresAt} and {step:'completed', sessionVersion}.

1. EmptyState, StatCard, Logo/LogoMark, PhoneLink, GenderAvatar, SectionTitle, LoadingBlock/PageSkeleton are server-safe. Nothing in these folders needs anything beyond LocaleProvider (already in root Providers). In vitest mock '@/i18n/client' (pattern in tests/effects-shared.test.tsx, which also stubs IntersectionObserver for framer's useInView and mocks sonner).

TicketAnimation and PageHeader (breadcrumb nav aria-label) likewise use tiny local uz/ru dictionaries; all other strings come from common.*.
3. Money: null/undefined/'' renders emptyText '—' (pass 0 explicitly for "0 soʻm"); unparsable strings also render '—'. suffix={null} = no currency.
4. DataTable `footer` is a ReactNode rendered in a bar under the table (intended for <Pagination/>), not a <tfoot>. Rows with onRowClick are keyboard-activatable (tabIndex 0, Enter/Space). stickyHeader wraps the table in a max-h-[70vh] scroll container.
5.
